# Creative Suite Hub 0.1.1

Status: **Unreleased**. Changes accumulated since the published 0.1.0 baseline.

## Fixed

- Persist each backup's original source path and distinguish same-named projects
  across directories and file extensions. Preserve project names containing
  `_backup_` and keep the association after restarting the Hub.
- Create each backup in an exclusive directory, preventing collisions during
  consecutive creation. Publish its identity record atomically after the
  snapshot is complete. Existing flat backups remain visible with unknown
  origin and are never assigned to a project by name alone.
- Display the original source path in backup rows, with full source/snapshot
  paths in the tooltip and an unknown-origin label for legacy entries.

- Discover the three editors in sibling `build/apps/<app-id>/<configuration>`
  directories when the Hub runs from its Release or Debug folder. Prefer the
  Hub's configuration, retain explicit installation-path priority, and handle
  single-configuration builds and macOS bundle executable paths.

- Keep every pending editor update monitored when multiple editors are open.
  Closing either editor starts its own installer; restarting the Hub resumes
  all pending apps. A failed or removed pending item no longer stops the others.
- Keep an app queued while its installer launch lock is occupied, without
  reporting a launch prematurely or duplicating monitored entries.

- Preserve relative media and linked-document references when Image, Video,
  and Motion projects are copied into the backup vault or relocated for
  restoration. Snapshots retain their document version and editing data;
  original projects and media remain unchanged. Media are referenced, not
  bundled, and older snapshots require their original directory context.
- Reject unsupported document versions and invalid reference structures with
  a logged cause, without publishing an incomplete snapshot.

## Improved

- Windows setup executables and installer wizards now display the Hub's
  application icon.

## Maintenance

- Add backup identity, persistence, legacy-record and malformed-record
  regressions, plus a widget test for distinguishing backup origins. Verify
  the new vault layout with the three editors' existing persistence code.

- Add discovery regressions for configuration selection, wrong-depth decoys,
  fallback paths, installation-path priority, and the enabled editors' actual
  CMake executable outputs.

- Add isolated installation-runtime regressions with real pending records,
  application leases, package verification, and simulated installer launches.
  Waiting polls read metadata and defer full package hashing until launch.

- Add producer/consumer backup regressions for all 46 currently supported
  document versions using the three editors' actual persistence code.

- Keep all ten Hub regression tests and the shared updater catalog test active
  in Release builds. Checks and required file setup are no longer removed by
  `NDEBUG`.
- Add a shared regression probe that verifies conditions are evaluated exactly
  once and that a deliberate failed check exits with a diagnostic identifying
  the file, line, and condition.
