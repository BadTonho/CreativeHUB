# Creative Suite Hub 0.1.1

Status: **Unreleased**. Changes accumulated since the published 0.1.0 baseline.

- Accept CSP v43 per-clip EQ/compressor chains with the existing audio mixer
  and track effect data in backup snapshots and restoration, retaining buses,
  Master settings, track pan/routes, sends, and ordered clip/track chains while
  preserving media path rebasing and Gallery sidecar behavior.
- Reject future CSP v44 and cover producer/consumer backup and manager paths.

## Update recovery and Hub diagnostics

- Store updater downloads, pending installs, and rollback snapshots under the
  persistent per-user data directory. Migrate the previous cache tree before
  resuming pending installs; retain HTTPS and same-catalog SHA-256 checks.
- Bound the persistent Hub log with a single rotated backup and reject
  changelog app/version path traversal. Keep updater UI adapters in each app.
- Persist update notifications and the Windows startup preference; hide the
  Windows-only startup control elsewhere. Show download progress in app cards.
- Move cache-size scans and project snapshot creation off the GUI thread while
  keeping refresh results and completion feedback on the owning page.

## Atomic Hub state persistence

- Save recent projects, activity records, backup settings, and backup snapshots
  through atomic file commits. Preserve the last valid in-memory project and
  activity lists when their persisted JSON is malformed, and log read/write
  failures with the affected path.

## Fixed

- Accept Video Editor CSP v29 backups with named Background compositions. Preserve graph data, masks and input offsets while relocating external Input paths; verify restored names and reject future v30.


- Accept Video Editor CSP v28 backups, preserving mask geometry, animation, typed connections and composition input offsets while relocating external Input paths. Reject unsupported future schemas and verify restored documents through the Video Editor reader.


- Accept Video Editor CSP v27 backups with Fusion Composition clips. Preserve
  Background/Text nodes and input-time offsets while relocating external graph
  inputs; cover restoration through the Video Editor reader and future-version
  rejection.

- Accept Video Editor `.csp` v26 backups, preserving adjustment duration,
  effects and transform curves without media-path lookup. Restore through the
  Video Editor reader is covered alongside supported older versions; future
  schemas remain rejected.

- Report partial or failed cache cleanup instead of always announcing success.
  Count only successfully removed file bytes, show the remaining cache size,
  and keep activity history consistent with the outcome. Empty caches have
  explicit feedback, and cancelling does not create an activity or error.
- Log cache-removal failures with the path, operation, cause, and error code;
  continue cleaning accessible entries and allow retry after unlocking files.
  Preserve cache roots and unrelated files, avoid counting overlapping roots
  or link targets twice, and detect newly created entries in the final check.

- Refresh each editor update service's installation version, destination,
  executable, and registration state without restarting the Hub. A first
  installation is recognized by later checks and the next update uses its
  registered destination. Removed registrations clear old installation data,
  and successful rollback refreshes the current version.
- Recheck installation data before setup and when opening update details.
  Skip packages already installed at the same or a newer version and block
  invalid installed versions with a logged cause. Keep active downloads intact
  during installation refresh.

- Persist each backup's original source path and distinguish same-named projects
  across directories and file extensions. Preserve project names containing
  `_backup_` and keep the association after restarting the Hub.
- Create each backup in an exclusive directory, preventing collisions during
  consecutive creation. Publish its identity record atomically after the
  snapshot is complete. Existing flat backups remain visible with unknown
  origin and are never assigned to a project by name alone.
- Display the original source path in backup rows, with full source/snapshot
  paths in the tooltip and an unknown-origin label for legacy entries.

- Discover the three editors in sibling `build/apps/<app-id>/<configuration>`
  directories when the Hub runs from its Release or Debug folder. Prefer the
  Hub's configuration, retain explicit installation-path priority, and handle
  single-configuration builds and macOS bundle executable paths.

- Keep every pending editor update monitored when multiple editors are open.
  Closing either editor starts its own installer; restarting the Hub resumes
  all pending apps. A failed or removed pending item no longer stops the others.
- Keep an app queued while its installer launch lock is occupied, without
  reporting a launch prematurely or duplicating monitored entries.

- Preserve relative media and linked-document references when Image, Video,
  and Motion projects are copied into the backup vault or relocated for
  restoration. Snapshots retain their document version and editing data;
  original projects and media remain unchanged. Media are referenced, not
  bundled, and older snapshots require their original directory context.
- Reject unsupported document versions and invalid reference structures with
  a logged cause, without publishing an incomplete snapshot.
