# Experimental Timeline GPU Composition: Delivery Evidence

Date: 2026-10-02. Video Editor is the first consumer. The opt-in remains disabled
by default. No project/application version or keyboard shortcut changes.

## Native Windows evidence

Host: Windows 11 build 26200, NVIDIA GeForce GTX 1660 SUPER, NVIDIA OpenGL driver
616.92, Qt 6.7.2, MSVC 2022, x64 Release. The context resolves OpenGL 3.2 Core.
Synthetic fixtures contain no private media and leave original files intact.

The shared native test runs on a worker using a GUI-created surface. It checks
exact alpha and dimensions and at most two RGB levels of difference against CPU,
including sparse text, patterned transparency, clipping, transforms, stride
padding, cancellation, device/request limits and repeated activation/shutdown.
The native timeline test requires GPU-composed frames, covers keyframes, text,
Cross Dissolve/Fade to Black, Full/Half/Quarter, queued toggle during playback,
and consumption/refresh of a masked PNG generated by the Image Editor core.
`CREATIVE_SUITE_DISABLE_GPU_PREVIEW=1` is enabled in that test to verify that it
controls presentation only. Unavailable contexts skip with code 77; shader,
pixel or lifecycle failures on a valid context fail the test.

This driver completed rotated fixtures using `ARB_gpu_shader_fp64` and
`ARB_gpu_shader5`, including 90-degree nearest-sampling boundary cases that failed
the initial FP32 shader. The forced `CoreOnly` policy passed unrotated parity and
correctly returned `Unsupported/check-precision` for rotation. On a driver
without these extensions, the native test reports limited rotation coverage;
that is CPU fallback coverage, not approval of GPU rotation.

## Measurement method

Run `creative-suite-composition-opengl-tests --benchmark` in Release. Three
sequential process runs were measured after builds/tests completed. Each run
warms both backends, then averages five compositions per size for two workloads:
an opaque 1920x1080 background with two transparent 1280x720 overlays (one scaled,
one rotated 23 degrees), and the opaque background alone. Source sizes remain
fixed when preview size changes. CPU includes composition/allocation; GPU total
includes context activation, geometry preparation, upload, submission,
synchronous readback, output allocation and row reversal. Submission is CPU
wall time, not a GPU execution query; readback also waits for submitted work.
The stage buckets are subcomponents, not an exhaustive sum of GPU total.

Times below are means of the three run averages; parentheses show their range.

| Workload | Preview | CPU total ms | GPU total ms |
| --- | --- | ---: | ---: |
| Three layers | Full 1920x1080 | 81.66 (80.75–83.30) | 7.37 (7.02–7.57) |
| Three layers | Half 960x540 | 21.12 (20.63–21.52) | 4.58 (4.35–4.81) |
| Three layers | Quarter 480x270 | 6.43 (6.25–6.68) | 3.69 (3.58–3.84) |
| One opaque layer | Full 1920x1080 | 2.64 (2.59–2.70) | 4.35 (4.27–4.44) |
| One opaque layer | Half 960x540 | 0.93 (0.89–0.98) | 2.73 (2.71–2.75) |
| One opaque layer | Quarter 480x270 | 0.25 (0.24–0.26) | 2.34 (2.23–2.41) |

| Workload | Preview | Upload ms | Submission ms | Readback ms | Uploaded bytes | Readback bytes |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Three layers | Full | 2.00 | 0.24 | 3.75 | 15,691,200 | 8,294,400 |
| Three layers | Half | 1.91 | 0.26 | 1.14 | 15,679,200 | 2,073,600 |
| Three layers | Quarter | 1.84 | 0.21 | 0.45 | 15,673,216 | 518,400 |
| One opaque layer | Full | 1.36 | 0.15 | 2.55 | 8,306,400 | 8,294,400 |
| One opaque layer | Half | 1.37 | 0.13 | 0.98 | 8,300,400 | 2,073,600 |
| One opaque layer | Quarter | 1.33 | 0.12 | 0.71 | 8,297,408 | 518,400 |

Uploaded bytes include the small geometry lookup. This measures synthetic
composition workloads, not presented FPS or a 15-minute audiovisual project.
The GPU improved the layered fixture; the optimized CPU path was faster for the
single opaque fixture at every quality. That tradeoff supports keeping the
preference off by default while direct texture delivery remains a later stage.
Existing local diagnostics before implementation showed CPU composition around
2.5–3.7 ms and much larger decode times in a few intervals; these uncontrolled
samples do not identify a universal bottleneck. No broad speedup is promised.

## Reproducible manual checklist

1. Open a timeline with video/audio, transparent stills, text, transform keyframes
   and both transitions. Record application build, OS, GPU and driver.
2. Toggle Settings > General > Use GPU for timeline preview (Experimental) while
   paused. Confirm current-frame refresh, unchanged playhead/dirty/history and
   persisted preference after reopening Settings/application.
3. Toggle while playing, change quality, seek/step quickly and inspect transition
   boundaries/black gaps. Confirm appearance, freshness and continuous audio.
4. Publish and republish a masked imported image in Image Editor; refresh the
   linked PNG in Video Editor. Compare CPU/GPU preview and the CPU export.
5. Force unsupported context/limits where the driver permits; verify logged
   context, brief status warning, continued CPU playback and preserved setting.
   Off/on retries technical failures. Close during rendering and reopen repeatedly.
6. Repeat with presentation disabled through the existing environment variable;
   composition preference still applies. Export/cancel keeps previous outputs.

These human/platform checks are pending unless a dated result is recorded here.
